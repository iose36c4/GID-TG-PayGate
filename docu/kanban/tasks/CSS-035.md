```javascript
// scripts/analyze-css.js - Análisis de bundle size
const fs = require('fs');
const path = require('path');

function analyzeCSS(file) {
  const css = fs.readFileSync(file, 'utf8');
  const lines = css.split('\n');
  const rules = lines.filter(l => l.includes('{') && !l.startsWith('@')).length;
  const size = Buffer.byteLength(css, 'utf8');
  
  console.log(`File: ${file}`);
  console.log(`  Size: ${(size / 1024).toFixed(2)} KB`);
  console.log(`  Rules: ${rules}`);
  console.log(`  Lines: ${lines.length}`);
}

// Analizar build output
const buildDir = 'public/build';
fs.readdirSync(buildDir).forEach(file => {
  if (file.endsWith('.css')) {
    analyzeCSS(path.join(buildDir, file));
  }
}
```

## Criterios de Aceptación
- [ ] Framework CSS modular: imports granulares por componente/utilidad
- [ ] PostCSS import resuelve paths del framework
- [ ] PurgeCSS elimina CSS no usado en producción
- [ ] Code splitting: entry points separados (app.css, dashboard.css, admin.css)
- [ ] Solo CSS necesario por página (ej: public no carga sidebar)
- [ ] Target bundle size: < 50KB gzipped framework completo
- [ ] Script de análisis: reporte rules, lines, KB
- [ ] Documentado en `docu/especificaciones/css-tree-shaking.md`

## Notas Técnicas
- `@import` en CSS nativo + PostCSS import (no ES modules)
- PurgeCSS safelist para dark mode, responsive, states, ARIA
- Code splitting por entry point (Vite cssCodeSplit)
- Framework CSS como librería: consumir via `@import 'framework/components/button'`
- Análisis post-build: rules count, KB gzipped

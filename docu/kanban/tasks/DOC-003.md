# [[DOC-003]] ADR-002: Single Users Table + Spatie Permissions

## Descripción
Documentar la decisión de usar una sola tabla `users` con Spatie Laravel Permission para roles/permisos.

## Código de Ejemplo
```markdown
# ADR-002: Single Users Table + Spatie Permissions

## Status
Accepted

## Context
Necesidad de gestionar usuarios con diferentes roles:
- **Superadmin**: Acceso total, configuración global
- **Admin**: Gestión staff, creadores, canales, transacciones
- **Staff**: Soporte tickets, facturación, moderación
- **Creador**: Gestión canales, analytics, retiros
- **Usuario/Cliente**: Compra accesos, gestiona suscripciones

## Decision
Usar **una sola tabla `users`** con columna `role` (enum) + **Spatie Laravel Permission** para permisos granulares.

### Diseño
```sql
-- users table
role ENUM('user', 'creador', 'staff', 'admin', 'superadmin') DEFAULT 'user'

-- Spatie tables (auto-creadas)
roles, permissions, model_has_permissions, model_has_roles, role_has_permissions
```

### Roles Base
| Role | Descripción | Permisos Clave |
|------|-------------|----------------|
| `superadmin` | Acceso total | `*`, manage superadmin |
| `admin` | Gestión plataforma | manage_staff, manage_creators, manage_channels, view_metrics |
| `staff` | Soporte/Operaciones | view_tickets, reply_tickets, manage_billing, view_metrics |
| `creador` | Gestión propia | manage_own_channels, view_own_analytics, request_payouts |
| `user` | Cliente final | view_own_subscriptions, purchase, create_tickets |

## Decision
Usar **tabla única `users` + Spatie Permission** para roles/permisos.

## Consecuencias
### Positivas
- Simplicidad: una tabla, una auth guard
- Spatie: probado en producción, permisos granulares, cache automático
- Flexibilidad: permisos por role + permisos directos por user
- Migración simple: solo añadir columna `role` a users existente
- Compatibilidad: `User::role()` + `$user->hasRole()`, `$user->can()`

### Negativas
- Todos los roles en una tabla (puede crecer)
- Permisos Spatie en BD (overhead mínimo)
- Row-level security requiere policies adicionales

## Alternativas Consideradas
1. **Tablas separadas por rol**: `admins`, `staffs`, `creators`, `users` - Complejo, joins necesarios
2. **Roles en JSON**: Flexible pero sin FK, queries complejas
3. **Roles en tabla separada + pivot**: Equivalente a Spatie pero sin librería

## Decision
**Aceptado**: Tabla única `users` + `role` enum + Spatie Laravel Permission.

## Consecuencias
- Migración simple: `role` enum en users + `spatie/laravel-permission` migration
- Middleware: `role:creador`, `role:staff|admin`, etc.
- Policies: `$user->can('manage_channels')`, `$user->hasRole('creador')`
- Seeding: Roles/Permisos en `RolePermissionSeeder`

## Consecuencias
- Positiva: Onboarding rápido, permisos flexibles
- Negativa: Cuidar que no se creen roles/permisos duplicados en runtime

- [[DOC-001]] Estructura docu
- [[FUN-005]] Spatie Permission implementación
```

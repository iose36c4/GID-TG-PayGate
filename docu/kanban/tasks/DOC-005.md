# [[DOC-005]] ADR-004: Deploy FTP Compartido + Symlinks

## Descripción
Documentar estrategia de deploy en InfinityFree (FTP) usando symlinks compartidos.

## Código de Ejemplo
```markdown
# ADR-004: Deploy FTP Compartido + Symlinks

## Status
Accepted

## Context
Deploy en InfinityFree (hosting compartido FTP) con limitaciones:
- Solo acceso FTP (sin SSH)
- Espacio limitado
- Sin acceso a CLI artisan en producción
- Carpeta pública: `/htdocs`

## Decision
Estrategia **FTP + Symlinks Compartidos**:
1. Build local → `public/build/` + `storage/app/public` → `vendor/`
2. Subir por FTP a `/htdocs/` + carpetas privadas fuera de `htdocs`
3. Symlinks en servidor para `storage` y `vendor` compartidos

## Estructura en Servidor
```
/home/user/
├── vendor/          # Compartido (symlink desde cada subdominio)
├── storage/         # Compartido (symlink desde cada subdominio)
├── public_html/     # Dominio principal (public)
├── creadores/       # Subdominio creadores (symlink a storage, vendor)
├── crm/             # Subdominio CRM
├── admin/           # Subdominio admin
```

## Implementation
```bash
# Deploy script (local)
#!/bin/bash
npm run build
php artisan config:cache
php artisan route:cache
php artisan view:cache

# Subir por lftp/rsync
lftp -c "
open -u $FTP_USER,$FTP_PASS $FTP_HOST
mirror -R --delete --parallel=5 public/ /htdocs/
mirror -R --delete --parallel=5 vendor/ /vendor/
mirror -R --delete --parallel=5 storage/app/public /storage/app/public
"

# En servidor (post-deploy SSH si disponible, o manual)
ln -sfn /home/user/vendor /htdocs/vendor
ln -sfn /home/user/vendor /home/user/creadores/vendor
ln -sfn /home/user/creadores/vendor /home/user/crm/vendor
ln -sfn /home/user/creadores/vendor /home/user/admin/vendor

ln -sfn /home/user/storage /home/user/public/storage
ln -sfn /home/user/storage /home/user/creadores/storage
ln -sfn /home/user/creadores/storage /home/user/crm/storage
ln -sfn /home/user/creadores/storage /home/user/admin/storage
```

## Decisión
**Aceptado**: Deploy FTP + Symlinks compartidos para vendor/storage.

## Consecuencias
- Positivo: Un solo `vendor` y `storage` para todos los subdominios
- Positivo: Deploy rápido (solo subir diffs)
- Positivo: Ahorro espacio disco
- Negativo: Requiere acceso SSH para crear symlinks (o panel de control)
- Negativo: Si falla symlink, todo cae

## Alternativas
1. **Copiar vendor/storage a cada subdominio**: Simple pero desperdicia espacio y tiempo
2. **Deploy independiente por subdominio**: Completo aislamiento pero 4x deploy time
3. **Git deploy en servidor**: Requiere SSH + composer install en servidor

## Decisión
**Aceptado**: Deploy FTP + Symlinks compartidos.

## Consecuencias
- Deploy script con lftp/rsync para sync incremental
- Script post-deploy para crear/verificar symlinks
- Monitoreo de espacio en disco compartido
- Rollback: mantener 3 versiones anteriores

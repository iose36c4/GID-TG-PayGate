# [[DOC-006]] ADR-005: Queue Driver Database (Portable) vs Redis

## Descripción
Documentar decisión de usar database queue driver para portabilidad vs Redis.

## Código de Ejemplo
```markdown
# ADR-005: Queue Driver Database vs Redis

## Status
Accepted

## Context
TG-PayGate necesita queue system para:
- Emails (verificación, facturas, notificaciones)
- Webhooks processing (MP, Stripe, PayPal)
- Telegram notifications
- Background jobs (reportes, retiros, facturación)
- Scheduler jobs (churn, retiros automáticos)

Opciones:
1. **Redis**: Rápido, features avanzados (delay, retry, horizon)
2. **Database**: Portable, sin dependencias externas, funciona en shared hosting
3. **Sync**: Solo desarrollo/testing

## Decision
Usar **Database Queue Driver** como default para portabilidad.

## Implementation
```env
# .env
QUEUE_CONNECTION=database
# QUEUE_CONNECTION=redis (opcional para producción dedicada)
```

```php
// config/queue.php
'connections' => [
    'database' => [
        'driver' => 'database',
        'table' => 'jobs',
        'queue' => 'default',
        'retry_after' => 90,
        'after_commit' => true,
    ],
    'redis' => [
        'driver' => 'redis',
        'connection' => 'default',
        'queue' => 'default',
        'retry_after' => 90,
        'block_for' => null,
    ],
],
```

## Decision
**Aceptado**: Database queue driver como default para portabilidad.

## Consecuencias
### Positivas
- Funciona en cualquier hosting (shared, VPS, serverless)
- Sin dependencias externas (Redis, Beanstalk, SQS)
- Zero-config en shared hosting
- Migración simple: `php artisan queue:table && php artisan migrate`

### Negativas
- Performance: ~10x más lento que Redis
- No delayed jobs nativos (workaround: `delay()`)
- No Horizon dashboard
- Polling constante (carga en DB)
- No rate limiting nativo

## Alternativas
1. **Redis**: Mejor performance, pero requiere Redis server
2. **Hybrid**: Database default + Redis opcional para production
3. **SQS/Beanstalkd**: Cloud-specific, vendor lock-in

## Decision
**Aceptado**: Database queue driver como default portable.

## Consecuencias
- Jobs usan `queue:work --sleep=3 --tries=3`
- Failed jobs table: `php artisan queue:failed-table`
- Retry logic: `--tries=3 --backoff=60`
- Monitoring: `php artisan queue:monitor`
- Escalado: `supervisord` con múltiples workers

## Alternativas Futuras
- v1.1: Redis opcional para producción alta carga
- Laravel Octane + RoadRunner para high throughput
- Horizon si se migra a Redis

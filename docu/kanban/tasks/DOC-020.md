# [[DOC-020]] ADR-009: Autorización — RBAC + Policies + ABAC/Tenancy

## Descripción
Documentar la arquitectura de **autorización** (independiente de autenticación): combinación de RBAC (roles + permisos atómicos), Laravel Policies por entidad financiera y ABAC/tenant scoping que garantiza que un creador solo opera sus propios recursos. Documentado también en `docu/arquitectura/autorizacion.md` (SEC-022).

## Código de Ejemplo
```markdown
# ADR-009: Arquitectura de Autorización

## Status
Accepted

## Contexto
- Autenticación ≠ autorización: "está logueado" no implica "puede reembolsar".
- El plan original tenía roles simples (user, creador, staff, admin) sin reglas por recurso.
- Riesgo IDOR (RSK-003): creador accediendo a pagos de otros.

## Decisión
1. **RBAC**: spatie/laravel-permission con roles granulares y permisos atómicos
   (`payments.refund`, `withdrawals.approve`, `settings.fiscal`).
2. **Laravel Policies** por entidad financiera (Invoice, Payment, Withdrawal, Refund, Dispute).
3. **ABAC/Tenancy**: scopes de Eloquent forzados a nivel de query — un creador ve/opera
   solo sus canales/pagos; staff/admin según contexto. Aplicado SIEMPRE (defensa en profundidad).
4. La decisión se toma en capa de dominio y se replica en API (scopes de Sanctum).

## Consecuencias
- Positivas: mínimo privilegio, cero IDOR, auditable.
- Negativas: más código de políticas; cualquier recurso nuevo exige su policy.

```

# [[DOC-021]] ADR-010: Seguridad de Webhooks y Telegram (firma, replay, DLQ)

## Descripción
Documentar las decisiones de seguridad del **borde de entrada**: verificación de firmas HMAC con ventana temporal y nonce (anti-replay), procesamiento en cola con retry/backoff y dead letter queue, y protección del webhook de Telegram con `secret_token`. Es la puerta de entrada de todo el dinero entrante.

## Código de Ejemplo
```markdown
# ADR-010: Seguridad de Webhooks y Telegram

## Status
Accepted

## Contexto
- Pasarelas (Stripe/MP) y Telegram llaman a nuestros webhooks; cualquiera podría imitarlos.
- Un replay o una firma falsa puede desencadenar cobros o estados inválidos.

## Decisión
1. **Verificación de firma** con `hash_equals` (tiempo constante) + ventana temporal (±5 min).
2. **Anti-replay**: nonce/timestamp único por evento; `update_id` en Telegram con UNIQUE.
3. **Procesamiento asíncrono**: responder `200` temprano, procesar en cola idempotente.
4. **Retry/backoff + DLQ**: eventos fallidos nunca se pierden; reproceso manual desde staff.
5. **Rotación de claves de firma** con key versioning (SEC-030/040).
6. **Telegram**: webhook con `secret_token` (origen verificado) + flood control por usuario.

## Consecuencias
- Positivas: sin cobros duplicados ni eventos falsos, recuperable.
- Negativas: latencia de entrega (procesamiento en cola), complejidad de verificación por proveedor.

```

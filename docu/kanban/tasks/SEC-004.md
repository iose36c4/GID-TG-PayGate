# [[SEC-004]] Security Baseline Transversal

## Descripción
Definir la **baseline de seguridad transversal** que aplica a todo el sistema y se reutiliza en todas las áreas: cabeceras HTTP, cifrado de datos en reposo, TLS, política de contraseñas/2FA, manejo de secretos, validación de entrada, protección CSRF, límites de petición por defecto y convenciones de código seguro. Documentada en `docu/arquitectura/seguridad/baseline.md`.

## Código de Ejemplo
```php
// app/Http/Kernel.php - baseline de middlewares globales
protected $middleware = [
    \App\Http\Middleware\SecureHeaders::class,        // CSP, HSTS, X-Frame-Options...
    \App\Http\Middleware\TrustProxies::class,          // correcto tras proxy
    \App\Http\Middleware\ValidateInputSize::class,     // límite payload
];

// config/security.php
return [
    'password_min_length' => 12,
    'two_factor' => ['required_for' => ['staff', 'admin', 'creador']],
    'sensitive' => ['telegram_token', 'payment_gateway_key', 'webhook_secret'],
    'rate_limit_default' => 60, // req/min por IP autenticada
    'tls' => ['min' => 'TLS1.2', 'hsts' => 'max-age=63072000; includeSubDomains'],
];
```

## Criterios de Aceptación
- [ ] `baseline.md` documentada con: headers, cifrado, auth, input validation, secretos, rate limit por defecto
- [ ] Middleware `SecureHeaders` implementado con CSP estricta (sin `unsafe-inline` salvo justificado y aprobado)
- [ ] Config `config/security.php` con todos los parámetros centralizados
- [ ] 2FA obligatorio para staff/admin/creador (factible con TST-S-006)
- [ ] Política de contraseñas aplicada (12+ chars, password managers)
- [ ] Baseline referenciada desde ADR y guías de desarrollo (DOC)

## Notas Técnicas
- Esta tarea es **bloqueante de facto** para implementaciones de pago y paneles
- Los valores por defecto deben ser seguros; relajar es decisión explícita y documentada
- Enlazar con INS-009 (seguridad instalador) y TST-S-010 (headers)
- No cifrar toda la DB: solo campos sensibles (ver SEC-040)

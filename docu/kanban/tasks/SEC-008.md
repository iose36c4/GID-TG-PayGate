# [[SEC-008]] Ledger de Doble Entrada Inmutable

## Descripción
Implementar el **libro mayor (ledger)** como registro inmutable de doble entrada. Todo movimiento de dinero es un conjunto de asientos `(account, debit, credit)` que debe cuadrar (`Σ debits = Σ credits`). Los balances **nunca** se guardan directamente: siempre son agregaciones del ledger. Esta es la decisión más crítica del sistema transaccional.

## Código de Ejemplo
```sql
-- migrations/..._create_ledger_tables.php
CREATE TABLE accounts (
  id          BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  code        VARCHAR(20) UNIQUE NOT NULL,   -- 'cash_platform', 'payable_creator'
  type        ENUM('asset','liability','equity','revenue','expense') NOT NULL,
  currency    CHAR(3) NOT NULL,
  name        VARCHAR(120) NOT NULL,
  created_at  TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE ledger_entries (
  id           BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  entry_group  CHAR(36) NOT NULL,            -- agrupa debit+credit del mismo evento
  account_id   BIGINT UNSIGNED NOT NULL,
  amount_cents BIGINT NOT NULL,              -- SIEMPRE positivo; signo vía debit/credit
  debit        BOOLEAN NOT NULL,
  currency     CHAR(3) NOT NULL,
  reference_id CHAR(36) NOT NULL,            -- payment_id, refund_id, withdrawal_id...
  description  VARCHAR(255) NOT NULL,
  created_at   TIMESTAMP(6) NOT NULL DEFAULT CURRENT_TIMESTAMP(6),
  CONSTRAINT uq_ledger_unique UNIQUE (entry_group, account_id),
  INDEX idx_ledger_account (account_id, created_at)
);
```

## Criterios de Aceptación
- [ ] Tablas `accounts` y `ledger_entries` creadas (inmutables: sin UPDATE/DELETE)
- [ ] Plan de cuentas inicial: `cash_platform`, `payable_creator`, `commission_revenue`, `fee_expense`, `pending_settlement`
- [ ] Servicio `LedgerService::post(EventoFinanciero $evento, array $asientos)` con validación de cuadre
- [ ] Cada asiento con `entry_group` (grupo transaccional) y `reference_id` (trazabilidad)
- [ ] **Sin** columna `balance` en tablas de negocio (Payment, Invoice, Wallet)
- [ ] Test: post con débitos ≠ créditos lanza `LedgerOutOfBalance`

## Notas Técnicas
- Inmutabilidad: trigger/soft-fail en DB impide UPDATE/DELETE de `ledger_entries`
- Usar `TIMESTAMP(6)` para microsegundos y orden cronológico exacto
- Los balances se obtienen por agregación (ver SEC-009); nunca por columna mutable
- Redis cache de balance solo como materialización, siempre invalidable por el ledger

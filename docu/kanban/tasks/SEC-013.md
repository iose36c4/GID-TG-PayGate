# [[SEC-013]] Máquina de Estados del Withdrawal (Retiro)

## Descripción
Máquina de estados del **retiro de creadores**: `Requested → Review | Approved → Processing → Paid | Failed | Rejected | Frozen`. El retiro solo es posible si el balance `payable_creator` del creador cubre el monto, y el cargo se realiza atómicamente contra el ledger al aprobarse (no antes).

## Código de Ejemplo
```php
enum WithdrawalState: string
{
    case Requested = 'requested';
    case Review = 'review';
    case Approved = 'approved';
    case Processing = 'processing';
    case Paid = 'paid';
    case Failed = 'failed';
    case Rejected = 'rejected';
    case Frozen = 'frozen';

    public function allowedTransitions(): array
    {
        return match ($this) {
            self::Requested => [self::Review, self::Rejected, self::Frozen],
            self::Review => [self::Approved, self::Rejected, self::Frozen],
            self::Approved => [self::Processing, self::Failed, self::Frozen],
            self::Processing => [self::Paid, self::Failed],
            default => [],
        };
    }
}

// Validación de fondos previa a aprobación
final class WithdrawalService
{
    public function request(Withdrawal $w, BalanceService $balances): void
    {
        $available = $balances->balanceOf('payable_creator', $w->currency->code);
        if ($available->amountInCents() < $w->amount->amountInCents()) {
            throw new InsufficientBalance($w->amount, $available);
        }
        $w->transitionTo(WithdrawalState::Review);
    }
}
```

## Criterios de Aceptación
- [ ] Enum `WithdrawalState` + transiciones
- [ ] Cargo al ledger solo al aprobar (transacción atómica con el cambio de estado)
- [ ] Chequeo de balance con `BalanceService` (agregado del ledger, nunca columna)
- [ ] `Review` obligatorio según umbral configurable (ej. > $X o primera vez)
- [ ] Mínimo de retiro y frecuencia configurados por creador (CRE-012)
- [ ] Evento `WithdrawalApproved` emitido (SEC-017)

## Notas Técnicas
- El cargo atómico evita doble retiro (ver SEC-020 concurrencia)
- Los retiros usan payouts de la pasarela (Stripe Connect / MP); el estado `Paid` requiere confirmación del payout
- Congelar retiros cuando el creador tiene disputas activas (SEC-015)
- Conectar con flujo de AFIP/retenciones (CRE-016)

# [[SEC-017]] Eventos de Dominio Financiero

## Descripción
Publicar **eventos de dominio** en el cambio de cada transición: `InvoiceCreated`, `PaymentSucceeded`, `PaymentFailed`, `RefundCreated`, `RefundCompleted`, `WebhookReceived`, `WithdrawalApproved`. Son la base de auditoría, integraciones (notificaciones, email, AFIP) y reprocesamiento. Implementar con `illuminate/events` o una cola de eventos persistida.

## Código de Ejemplo
```php
// app/Domains/Financiero/Events/PaymentSucceeded.php
final class PaymentSucceeded
{
    public function __construct(
        public readonly Payment $payment,
        public readonly string $correlationId,
        public readonly Carbon $occurredAt,
    ) {}
}

// Emisión desde el servicio de dominio
event(new PaymentSucceeded($payment, $request->correlationId(), now()));

// Listener -> ledger post, factura, notificación, invite link
[
    'PaymentSucceeded' => [PostLedgerEntry::class, MarkInvoicePaid::class, SendInvite::class],
]
```

## Criterios de Aceptación
- [ ] Eventos definidos: InvoiceCreated, PaymentSucceeded, PaymentFailed, RefundCreated, RefundCompleted, WebhookReceived, WithdrawalApproved
- [ ] Cada evento: `aggregate_id`, `type`, `payload`, `correlation_id`, `occurred_at`, `actor`
- [ ] Publicados en transacción de dominio (fallo de listener no revierte el evento fuente, ver notas)
- [ ] Listeners mapeados a acciones (ledger, factura, notificación, invite)
- [ ] Documentación del catálogo de eventos en `docu/arquitectura/eventos.md`
- [ ] Replay posible desde event store (SEC-018)

## Notas Técnicas
- Patrón: **transaccional outbox** para publicar eventos fiables (o disparar después del commit)
- No mezclar: el evento describe qué pasó; los listeners ejecutan efectos
- Incluir `correlation_id` (SEC-037) en todo evento para trazabilidad E2E
- Convención: verbo en pasado (`PaymentSucceeded`), sustantivo del agregado

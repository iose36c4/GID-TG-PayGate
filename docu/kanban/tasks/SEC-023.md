# [[SEC-023]] Laravel Policies por Entidad Financiera

## Descripción
Implementar las **Policies de Laravel** para todas las entidades financieras: `Invoice`, `Payment`, `Withdrawal`, `Refund`, `Dispute`, `LedgerEntry`, `Account`. Cada método (view, create, refund, cancel, approve, list) con regla clara y testeada. Cubre la matriz creador→recurso propio, staff→global, admin→todo.

## Código de Ejemplo
```php
// app/Domains/Financiero/Policies/PaymentPolicy.php
class PaymentPolicy
{
    use HandlesAuthorization;

    public function view(User $user, Payment $payment): Response
    {
        return $user->id === $payment->creator_id
            || $user->hasAnyRole(['staff', 'admin'])
            || $user->id === $payment->customer_id
                ? Response::allow()
                : Response::deny('No tienes acceso a este pago');
    }

    public function refund(User $user, Payment $payment): Response
    {
        if (!$payment->state->is(Paid)) return Response::deny('Pago no reembolsable');
        if ($user->hasRole('admin') || $user->hasRole('staff')) return Response::allow();
        return $user->id === $payment->creator_id
            ? Response::allow()
            : Response::deny('Solo staff o el creador pueden reembolsar');
    }
}
```

## Criterios de Aceptación
- [ ] Policies: Invoice, Payment, Withdrawal, Refund, Dispute, LedgerEntry, Account
- [ ] Métodos: view, create, update (solo transiciones válidas), refund, cancel, approve, list
- [ ] Regla tenancy: creador solo sobre sus recursos (nunca `Payment::all()` de otro)
- [ ] Deny siempre con motivo; auditado en SEC-036
- [ ] Tests de Policies (100% de métodos) en matriz de roles (SEC-027)
- [ ] Usadas tanto en controladores como en servicios de dominio

## Notas Técnicas
- Las Policies protegen el **dominio**, no solo la API: replicar checks en servicios
- `viewAny`/`list` debe filtrar por creador/scope, no devolver todo y filtrar en UI
- Complementar con ABAC/atributos (SEC-025) para reglas condicionales
- Evitar `before()` abusivo: explícito es más auditable

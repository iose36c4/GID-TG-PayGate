# [[SEC-024]] RBAC Escalable: Roles + Permisos + Contextos

## Descripción
Ampliar el RBAC base (user, creador, staff, admin) a un modelo **escalable**: roles granulares (creador, colaborador-creador, staff-soporte, staff-finanzas, admin), permisos atómicos (`payments.refund`, `withdrawals.approve`, `settings.fiscal`), y contexto (scope de datos) que limita qué datos ve cada rol. Documentar la matriz completa.

## Código de Ejemplo
```php
// roles + permisos con spatie/laravel-permission
$roles = [
    'creador'          => ['channels.manage', 'payments.view', 'withdrawals.request'],
    'colaborador'      => ['channels.view', 'analytics.view', 'tickets.manage'],
    'staff-soporte'    => ['tickets.manage', 'customers.view', 'channels.suspend'],
    'staff-finanzas'   => ['payments.refund', 'withdrawals.approve', 'reconcile.run'],
    'admin'            => ['*'],
];

// Usuario con roles múltiples: creador de canal A + colaborador de canal B
$user->assignRole('creador');
$user->assignRole(['staff-finanzas']);

// Contexto (qué puede ver) separado del permiso (qué puede hacer)
$user->can('payments.refund') && $payment->creator_id === $user->id;
```

## Criterios de Aceptación
- [ ] Matriz de roles × permisos documentada (5+ roles, 20+ permisos atómicos)
- [ ] Permisos atómicos con convención `dominio.accion` (`payments.refund`)
- [ ] Soporte de múltiples roles por usuario (spatie)
- [ ] Colaborador/equipo de creador con scopes (CRE-010) y permisos limitados
- [ ] Seeders reproducibles + test de que cada rol tiene exactamente sus permisos
- [ ] UI de gestión de roles/permisos en admin (ADM-003)

## Notas Técnicas
- No "romper" el RBAC con `before()` globales no auditables
- Combinar con Policies (SEC-023) y ABAC/atributos (SEC-025)
- El contexto de datos se aplica SIEMPRE además del permiso (defensa en profundidad)
- La asignación de roles sensibles (staff-finanzas, admin) requiere 2FA + audit (SEC-036)

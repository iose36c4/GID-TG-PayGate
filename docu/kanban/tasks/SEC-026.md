# [[SEC-026]] Scopes API + Service Tokens

## Descripción
Diseñar la **autorización de API** con scopes (permisos sobre tokens): `read:channels`, `write:webhooks`, `read:payments`, `withdrawals:request`. Tokens de creador (CRE-008) y service tokens internos (webhook saliente, jobs) con expiración, rotación y revocación. Basado en Sanctum con abilities.

## Código de Ejemplo
```php
// Crear token con scopes
$token = $user->createToken('api-cli', ['read:channels', 'write:webhooks']);

// Middleware de scope (Sanctum ability)
Route::get('/api/v1/channels', fn () => ...)
    ->middleware(['auth:sanctum', 'abilities:read:channels']);

// Verificar con tokenCan en servicios
if (!$request->user()->tokenCan('write:webhooks')) {
    throw new AuthorizationException('Scope requerido: write:webhooks');
}

// Rotación: revocar anterior + emitir nuevo (con hash del token)
$token->revoke();
```

## Criterios de Aceptación
- [ ] Catálogo de scopes definido y documentado
- [ ] Tokens Sanctum con abilities, hash en DB (nunca token plano), expiración
- [ ] Rotación de tokens (revocar + emitir) con historial de auditoría
- [ ] Revocación inmediata y listado en UI creador (CRE-008)
- [ ] Service tokens para integraciones internas con permisos mínimos y aislados
- [ ] Tests: scope faltante → 403; scope presente → acceso

## Notas Técnicas
- Scope = capacidad; tenant scope (SEC-025) = datos; se aplican ambos
- Nunca emitir tokens con `*` salvo admin y con aprobación explícita
- Guardar solo hash del token (`token` de Sanctum ya es hash)
- Rate limiting específico por token (SEC-033)

# [[SEC-028]] Webhook Verification: Firma, Timestamp, Nonce, Replay

## Descripción
Implementar la **verificación de webhooks entrantes** (pasarelas y proveedores): firma HMAC/timestamp del proveedor, ventana temporal (anti-replay), nonce, idempotencia y respuesta temprana `200` antes de procesar. Rechazo con `400`/`410` y logging de auditoría. Es la puerta de entrada de todo dinero entrante.

## Código de Ejemplo
```php
// app/Http/Middleware/VerifyWebhookSignature.php
class VerifyWebhookSignature
{
    public function handle(Request $request, Closure $next): Response
    {
        $provider = ProviderRegistry::fromHeader($request); // 'stripe' | 'mercadopago' | ...
        $secret   = $provider->currentSecret();              // rotación soportada

        $signature = $provider->signatureFrom($request);
        $payload   = $request->getContent();

        // 1) Firma
        if (!hash_equals($signature, $provider->sign($payload, $secret))) {
            abort(400, 'Firma inválida');
        }

        // 2) Timestamp anti-replay (ventana ±5min)
        $ts = $provider->timestampFrom($request);
        if (abs(time() - $ts) > 300) abort(400, 'Webhook expirado');

        // 3) Nonce: rechazar reuso
        if (!WebhookNonce::consume($provider->id(), $ts . ':' . $request->header('X-Nonce'))) {
            abort(400, 'Nonce reutilizado');
        }

        return $next($request);
    }
}
```

## Criterios de Aceptación
- [ ] Middleware `VerifyWebhookSignature` aplicado a todas las rutas `/webhooks/*`
- [ ] Firma verificada con `hash_equals` (tiempo constante)
- [ ] Ventana temporal anti-replay configurada (±5 min) y testeada
- [ ] Nonce único por evento → replay rechazado (vínculo SEC-016 idempotencia)
- [ ] Respuesta `200` inmediata + procesamiento en cola
- [ ] Evento `WebhookReceived` auditado con firma válida/inválida (SEC-017/036)
- [ ] Firma inválida → 400 + rate limit IP (SEC-033)

## Notas Técnicas
- Cada proveedor (Stripe, MercadoPago, PayPal) tiene esquema de firma distinto: abstraer en `ProviderRegistry`
- Soporte de rotación de secretos: verificar contra versión actual y anterior (SEC-030/040)
- Nunca loguear el payload completo si contiene datos personales
- El procesamiento ocurre en job con idempotencia (SEC-016)

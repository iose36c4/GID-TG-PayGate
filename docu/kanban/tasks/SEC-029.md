# [[SEC-029]] Webhook Retry + Backoff + Dead Letter Queue

## Descripción
Procesamiento confiable de webhooks: trabajo en cola con **reintentos con backoff exponencial + jitter**, umbral máximo, **dead letter queue (DLQ)** para eventos fallidos, reprocesamiento manual desde staff y reporte de entregas. Garantiza que ningún evento de pago se pierda sin resolución.

## Código de Ejemplo
```php
// app/Jobs/ProcessWebhookJob.php
class ProcessWebhookJob implements ShouldQueue
{
    public int $tries = 8;
    public array $backoff = [30, 60, 120, 300, 600, 1800, 3600]; // s
    public int $timeout = 60;

    public function handle(WebhookDelivery $delivery): void
    {
        try {
            $this->dispatcher->dispatch($delivery->payload);   // idempotente
            $delivery->markProcessed();
        } catch (ProviderTransientError $e) {
            throw $e; // reintenta con backoff
        } catch (UnrecoverableError $e) {
            $delivery->markDead(); // -> DLQ
            $this->release();
        }
    }

    public function failed(Throwable $e): void
    {
        // Entra en la DLQ: `webhook_deliveries` con status=dead
        Log::critical('Webhook falló definitivamente', [
            'delivery_id' => $this->delivery->id,
            'correlation_id' => $this->delivery->correlation_id,
        ]);
    }
}
```

## Criterios de Aceptación
- [ ] Cola de procesamiento con `tries`, `backoff[]` y `timeout`
- [ ] DLQ: tabla/status `webhook_deliveries` con estado `dead` + motivo
- [ ] Reproceso manual de DLQ desde staff (UI + comando `webhook:reprocess <id>`)
- [ ] Monitorización de DLQ (SEC-038): alerta si tamaño > umbral
- [ ] Todos los webhooks procesados una sola vez (idempotencia, SEC-016)
- [ ] Tests: fallo transitorio → reintenta; fallo permanente → DLQ

## Notas Técnicas
- Backoff no puede exceder el plazo del proveedor (Stripe/MP reintentan su lado ~3 días)
- El `webhook_deliveries` guarda cada intento (attempts, error, status_code)
- Distinguir errores transitorios (5xx/timeout) de permanentes (422/validation)
- Conectar con `queue:failed` de Laravel para alertas globales

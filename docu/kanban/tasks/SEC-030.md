# [[SEC-030]] Webhook Delivery Log + Rotación de Claves de Firma

## Descripción
Persistir el **log de entregas de webhook** (recibido, intentos, respuestas, errores, estado) y gestionar la **rotación de claves de firma**: múltiples versiones válidas con solapamiento, comando de rotación, invalidación posterior y regeneración de emergencia. Los webhooks salientes del creador (CRE-007) usan el mismo mecanismo.

## Código de Ejemplo
```sql
CREATE TABLE webhook_deliveries (
  id             BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  provider       VARCHAR(30)  NOT NULL,          -- 'stripe'|'mercadopago'|'creator'
  event_id       VARCHAR(100) NOT NULL,          -- id del evento del proveedor
  payload_hash   CHAR(64)     NOT NULL,
  status         ENUM('received','processing','processed','dead') NOT NULL,
  attempts       TINYINT      NOT NULL DEFAULT 0,
  last_error     VARCHAR(500) NULL,
  correlation_id CHAR(36)     NOT NULL,
  received_at    TIMESTAMP    NOT NULL,
  processed_at   TIMESTAMP    NULL,
  UNIQUE KEY uq_provider_event (provider, event_id)
);
```

```php
// Rotación de secretos (command artisan webhook:rotate-keys --provider=stripe)
// 1) Generar nuevo secreto y guardarlo como versión vigente (key_version)
// 2) Publicar nuevo secreto en pasarela (API provider)
// 3) Mantener versión anterior válida N días (verificación dual en SEC-028)
// 4) Invalidar versión antigua y re-verificar entregas
```

## Criterios de Aceptación
- [ ] Tabla `webhook_deliveries` con UNIQUE(provider, event_id) (idempotencia de registro)
- [ ] Log de intentos y errores visible en staff (CRE-007)
- [ ] Mecanismo de rotación con `key_version` y ventana de solapamiento
- [ ] Verificación de firma contra versión actual y anterior (SEC-028)
- [ ] Rotación programada (cada 90 días) + rotación manual de emergencia
- [ ] Test: verificación con clave vieja durante ventana → aceptada; después → rechazada

## Notas Técnicas
- Las claves viven en Secret Management (SEC-040), nunca en el repo
- El UNIQUE(provider, event_id) previene doble registro de un mismo evento
- Loguear versión de clave usada en cada verificación para auditoría
- Extender a webhooks salientes de creadores (firma propia del creador)

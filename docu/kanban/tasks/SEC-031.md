# [[SEC-031]] Seguridad Telegram: Firma, Replay, Origen

## Descripción
Endurecer la integración con **Telegram Bot API**: validación de origen de los updates (solo el servidor de Telegram puede llamar al webhook), secreto de webhook (`secret_token`), verificación de `update_id` para evitar replay, validación de timestamps en bot commands y prevención de abuso del bot (comandos, invite links).

## Código de Ejemplo
```php
// 1) setWebhook con secret_token (Telegram lo envía en X-Telegram-Bot-Api-Secret-Token)
Telegram::setWebhook(['url' => $url, 'secret_token' => $secret]);

// 2) Middleware de verificación
class VerifyTelegramWebhook
{
    public function handle(Request $request, Closure $next): Response
    {
        if (!hash_equals($request->header('X-Telegram-Bot-Api-Secret-Token', ''), config('telegram.secret_token'))) {
            abort(400, 'Origen no válido');
        }

        $updateId = $request->json('update_id');
        if (TelegramUpdate::where('update_id', $updateId)->exists()) {
            return response()->json(['ok' => true, 'replayed' => true]); // replay: responder sin reprocesar
        }
        TelegramUpdate::insert(['update_id' => $updateId, 'received_at' => now()]);

        return $next($request);
    }
}
```

## Criterios de Aceptación
- [ ] Webhook registrado con `secret_token` (nunca vía query param público)
- [ ] Middleware verifica header secreto con `hash_equals`
- [ ] `update_id` persistido con UNIQUE → replay responde `ok` sin reprocesar
- [ ] Validación de timestamps en comandos de pago (ventana ±60s)
- [ ] Comandos con nonce único (pago único por intento)
- [ ] Límite de comandos por usuario (anti-flood, SEC-032)
- [ ] Tests: update falso, replay, timestamps vencidos

## Notas Técnicas
- El `secret_token` es el control de autenticación del origen: es obligatorio
- No confiar en `message.from.id` para autorización sin cruzar con datos del proveedor
- Invite links: `member_limit=1` + expiración (PUB-008) para evitar filtraciones
- Loguear update_id/telegram_id en auditoría (SEC-036), sin contenido de mensajes privados innecesario

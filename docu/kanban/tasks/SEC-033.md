# [[SEC-033]] Rate Limiting por Área (Multi-Perfil)

## Descripción
Definir e implementar **rate limiting por área** con límites distintos y adecuados a cada superficie: login, registro, Telegram, payment, invoice, withdraw, admin api, public api y webhook. Bypass el límite genérico único de Laravel; límites por IP, por usuario y por token, con respuestas `429` y `Retry-After`.

## Código de Ejemplo
```php
// bootstrap/app.php (Laravel 11)
->withMiddleware(function (Middleware $middleware) {
    $middleware->throttleApi('60,1');                      // API pública
    $middleware->throttle('auth.login', '5,1');            // login por IP+email
    $middleware->throttle('payments.create', '10,1');      // crear pago
    $middleware->throttle('withdrawals.request', '5,1');   // retiros
    $middleware->throttle('webhook.verify', '100,1');      // webhooks (por proveedor/IP)
});

// config/rate-limits.php
return [
    'login'        => ['max' => 5,  'decay' => 60],
    'register'     => ['max' => 3,  'decay' => 3600],
    'telegram'     => ['max' => 30, 'decay' => 60],
    'payments'     => ['max' => 10, 'decay' => 60],
    'invoices'     => ['max' => 20, 'decay' => 60],
    'withdrawals'  => ['max' => 5,  'decay' => 3600],
    'admin'        => ['max' => 300,'decay' => 60],
    'public_api'   => ['max' => 60, 'decay' => 60],
    'webhook'      => ['max' => 200,'decay' => 60],
];
```

## Criterios de Aceptación
- [ ] Límites por área centralizados en `config/rate-limits.php`
- [ ] Aplicados: login, register, telegram, payment, invoice, withdraw, admin, public api, webhook
- [ ] Clave compuesta: IP + usuario/email + token donde aplique
- [ ] Respuestas `429` con `Retry-After` y cuerpo descriptivo
- [ ] Bypass a `/webhooks` solo para IPs/proveedores verificados (allowlist) NO para rutas públicas
- [ ] Tests de cada límite (no exceder, exceder, recuperación)

## Notas Técnicas
- Distinguir límites "por IP" (anónimos) de "por usuario" (autenticados, ej. 5 retiros/hora)
- El rate limit es mitigación de fuerza bruta, flood y DoS parcial (SEC-033)
- Los límites altos de admin protegen paneles internos sin bloquear trabajo real
- Alertar cuando una IP/token dispara límites repetidamente (SEC-036/038)

# [[SEC-034]] Scheduler: Expirar Invoices, Retry Webhooks, Orphans, Limpieza

## Descripción
Definir el **scheduler de Laravel** con todos los procesos programados del dominio: expirar invoices (`PendingPayment` vencidas → `Expired`), reintentar webhooks caídos, detectar pagos huérfanos, limpiar tokens/idempotency records vencidos, cierre de día contable y verificación de jobs fallidos. Cada job con lock distribuido (SEC-021) y monitoreo.

## Código de Ejemplo
```php
// routes/console.php (Laravel 11)
Schedule::call(fn () => app(ExpireInvoices::class)->run())
    ->everyFiveMinutes()
    ->withoutOverlapping(10)
    ->onFailure(fn () => Log::critical('ExpireInvoices falló'));

Schedule::command('webhook:retry-overdue')
    ->everyFiveMinutes()
    ->withoutOverlapping(15);

Schedule::call(fn () => app(OrphanPaymentScanner::class)->run())
    ->everyTenMinutes()
    ->onFailure(ReportCritical::class);

Schedule::command('tokens:purge-expired')
    ->dailyAt('03:10')
    ->withoutOverlapping();

Schedule::command('reconcile:run')
    ->dailyAt('04:00')
    ->withoutOverlapping(60); // ver SEC-019
```

## Criterios de Aceptación
- [ ] Todos los jobs programados definidos con frecuencias y `withoutOverlapping`
- [ ] Expiración de invoices automática y auditada (evento `InvoiceExpired`)
- [ ] Retry de webhooks atrasados (`webhook:retry-overdue`)
- [ ] Escáner de pagos huérfanos (payment sin invoice/ledger) → alerta
- [ ] Purga de tokens, idempotency records y sesiones vencidas
- [ ] Logs/alertas de cada job fallido (SEC-038) y ejecución en staging verificada
- [ ] Documentado en `docu/runbooks/scheduler.md`

## Notas Técnicas
- En alojamientos sin cron del proveedor, usar `Schedule::work()` (Laravel 11) o alternativa documentada en DOC-010
- `withoutOverlapping` con lock Redis para no duplicar ejecuciones
- Los jobs que tocan dinero deben ser idempotentes (SEC-016)
- Cada ejecución registra duración/resultado para observabilidad

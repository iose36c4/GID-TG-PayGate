# [[SEC-035]] Job Retry Pipeline + Dead Letter Queue (General)

## Descripción
Pipeline general de jobs para todo el sistema (no solo webhooks): reintentos con backoff configurado por job, clasificación de errores (transitorio vs permanente), **dead letter queue** unificada, dashboard de jobs fallidos y alertas. Garantiza que cobros, notificaciones y conciliaciones se completen o escalen.

## Código de Ejemplo
```php
// app/Jobs/AbstractFinancialJob.php
abstract class AbstractFinancialJob implements ShouldQueue
{
    public int $tries = 6;
    public array $backoff = [10, 30, 60, 300, 900];
    public int $timeout = 90;

    final public function handle(): void
    {
        try {
            $this->runWithIdempotency();      // SEC-016
        } catch (TransientException $e) {
            throw $e;                          // reintenta
        } catch (PermanentException $e) {
            $this->markDead($e);               // DLQ
            throw $e;
        }
    }

    abstract protected function runWithIdempotency(): void;
    abstract public function markDead(Throwable $e): void;
}
```

```bash
# Monitoreo de cola
php artisan queue:monitor --jobs='charge-subscription,expire-invoice,reconcile-day' --max=10
php artisan queue:failed --table=failed_jobs   # DLQ unificada
```

## Criterios de Aceptación
- [ ] Clases base de jobs con `tries`, `backoff`, `timeout` y clasificación de errores
- [ ] DLQ unificada (`failed_jobs` + tabla de dominios para reproceso)
- [ ] Comando de reproceso selectivo `job:retry <id|all>`
- [ ] Dashboard de jobs fallidos y DLQ en staff/admin
- [ ] Alertas por umbral (jobs fallidos > N en 1h)
- [ ] Tests: fallo transitorio reintenta; permanente va a DLQ; reproceso funciona

## Notas Técnicas
- Aplicar a jobs de dinero: charge subscription, expire invoice, process webhook, reconcile
- `queue:monitor` de Laravel para el sizing de la DLQ
- Nunca reintentar sin idempotencia en el job (doble cobro)
- Timeout menor al del worker; backoff mayor al tiempo de recuperación típico

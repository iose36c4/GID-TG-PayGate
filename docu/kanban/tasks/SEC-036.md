# [[SEC-036]] Audit Log Completo (Actor, IP, Payload Hash, Correlation ID)

## Descripción
Implementar el **audit log** como registro inmutable de acciones sensibles: quién (actor), cuándo, desde dónde (IP, user-agent), qué (payload hash), resultado (response hash), cambios, y `correlation_id` para trazabilidad. Cubre: login, cambios de rol/permiso, transiciones financieras, refunds, retiros, suspensión de canales, y accesos de staff.

## Código de Ejemplo
```sql
CREATE TABLE audit_logs (
  id             BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  actor_type     VARCHAR(20),                 -- 'user'|'system'|'webhook'|'cron'
  actor_id       VARCHAR(40),
  action         VARCHAR(100) NOT NULL,       -- 'payment.refunded'
  resource_type  VARCHAR(60) NOT NULL,
  resource_id    VARCHAR(40) NOT NULL,
  ip             VARCHAR(45),
  user_agent     VARCHAR(255),
  payload_hash   CHAR(64),                    -- sha256 del request sensible
  response_hash  CHAR(64),
  changes        JSON,                        -- diff {field: [old, new]}
  correlation_id CHAR(36) NOT NULL,
  created_at     TIMESTAMP(6) NOT NULL DEFAULT CURRENT_TIMESTAMP(6),
  INDEX idx_audit_resource (resource_type, resource_id),
  INDEX idx_audit_correlation (correlation_id),
  INDEX idx_audit_created (created_at)
);
```

```php
// app/Http/Middleware/AuditLog.php + AuditLogger service
AuditLogger::record('payment.refunded', $payment, [
    'ip' => $request->ip(),
    'user_agent' => $request->userAgent(),
    'payload_hash' => hash('sha256', $request->getContent()),
    'changes' => ['state' => ['paid', 'refund_requested']],
]);
```

## Criterios de Aceptación
- [ ] Tabla `audit_logs` inmutable (sin UPDATE/DELETE) con índices
- [ ] Acciones auditadas: auth, permisos, financieras, staff, suspensión, configuración crítica
- [ ] Actor, IP, user-agent, hashes, changes y correlation_id en cada registro
- [ ] Hash de payload sin guardar datos sensibles en claro
- [ ] Consulta/UI de auditoría en staff/admin con filtros (ADM-007)
- [ ] Retención configurable + exportación para compliance (TST-S-012)
- [ ] No se loguea PII innecesaria (SEC-039)

## Notas Técnicas
- El payload se hashea, no se guarda en claro (tarjetas, tokens, emails)
- `correlation_id` (SEC-037) conecta request → events → audit → logs
- Es la fuente primaria para investigaciones de seguridad y compliance
- La inmutabilidad se refuerza con permisos de DB (usuario de app sin UPDATE)

# [[SEC-037]] Correlation IDs (X-Correlation-ID)

## Descripción
Implementar **correlation IDs** en todo el sistema: `X-Correlation-ID` aceptado del cliente (validado UUID) o generado, propagado a través de middleware → controladores → servicios → jobs → llamadas externas → logs → eventos → auditoría. Habilita trazar una operación de pago de extremo a extremo.

## Código de Ejemplo
```php
// app/Http/Middleware/CorrelationId.php
class CorrelationId
{
    public function handle(Request $request, Closure $next): Response
    {
        $header = $request->header('X-Correlation-ID');
        $correlationId = ($header && Str::isUuid($header)) ? $header : (string) Str::uuid();

        app()->instance('correlation_id', $correlationId);
        Log::withContext(['correlation_id' => $correlationId]);

        $response = $next($request);
        $response->headers->set('X-Correlation-ID', $correlationId);

        return $response;
    }
}

// En jobs: propagar al dispatch
dispatch(new ProcessWebhook($delivery))->withCorrelation($correlationId);

// En llamadas salientes
$client->withHeaders(['X-Correlation-ID' => $correlationId])->post(...);
```

## Criterios de Aceptación
- [ ] Middleware `CorrelationId` global (genera o valida UUID)
- [ ] Header devuelto en toda respuesta
- [ ] Logs con contexto `correlation_id` (vía `Log::withContext`)
- [ ] Jobs propagan el id (no generan uno nuevo)
- [ ] Llamadas HTTP salientes incluyen el header
- [ ] Eventos y audit logs guardan `correlation_id` (SEC-017/036)
- [ ] Búsqueda E2E por correlation_id en logs/auditoría

## Notas Técnicas
- Nunca confiar en el header del cliente para lógica de negocio: solo trazabilidad
- Validar UUID para evitar abuso de header (inyección)
- Si un job se despacha sin id, generar y registrar la pérdida (problema de trazabilidad)
- Complemento directo de SEC-036 (audit) y SEC-038 (traces)

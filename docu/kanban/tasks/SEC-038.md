# [[SEC-038]] Observabilidad: OpenTelemetry, Métricas, Alerting

## Descripción
Implementar **observabilidad** del sistema transaccional: tracing distribuido con OpenTelemetry, métricas de negocio y sistema (PII-free) exportables a Prometheus, dashboards en Grafana y **alertas** (DLQ grande, reconciliación fallida, transacciones lentas, errores 5xx, rate limit abuses). El objetivo: detectar incidentes financieros en minutos, no días.

## Código de Ejemplo
```php
// app/Support/Observability/OpenTelemetry.php
$tracer = TracerProvider::getTracer('tg-paygate');

$span = $tracer->spanBuilder('payment.confirm')
    ->setAttribute('payment.id', $payment->id)          // sin PII
    ->setAttribute('channel.id', $payment->channel_id)
    ->setAttribute('provider', $provider)
    ->startSpan();

// Métricas de negocio
$meter = MeterProvider::getMeter('tg-paygate');
$meter->createCounter('payments.total', 'El total de pagos confirmados')
    ->add(1, ['provider' => $provider, 'currency' => $currency]);

$meter->createHistogram('payment.confirm.duration_ms')->record($durationMs);

// Alertas (config/prometheus-rules.yml)
//  - increase(tg_payments_failed_total[15m]) > 3   -> page on-call
//  - reconcile_success == 0 (hoy)                  -> critical
//  - dlq_size > 50                                 -> warning
```

## Criterios de Aceptación
- [ ] SDK OpenTelemetry instalado + exporters configurados
- [ ] Spans en los flujos: confirmación de pago, webhook, refund, retiro, login
- [ ] Métricas: payments (total/failed), webhooks (received/replayed/dead), dlq_size, latency, rate limit hits
- [ ] Prometheus scrape + dashboards Grafana (4+ paneles)
- [ ] Alertas configuradas con thresholds y rutas (email/telegram staff)
- [ ] Sin PII en métricas/traces (solo IDs técnicos)
- [ ] Trace conectado a correlation_id (SEC-037)

## Notas Técnicas
- Las métricas nunca contienen emails, montos de usuarios o datos personales
- Redis/queue del proveedor en InfinityFree es limitado: definir nivel mínimo viable (logs estructurados + métricas de negocio en DB)
- Documentar en runbooks los dashboards y alertas (DOC-015)
- Alertas de negocio (reconciliación) tan importantes como las técnicas

# [[SEC-039]] Structured Logging sin PII ni Secretos

## Descripción
Centralizar el **logging estructurado** (JSON) con niveles, canales, y **reglas estrictas: nunca PII ni secretos en logs**. Configurar formatters por canal (stderr JSON en prod, pretty en dev), enmascaramiento automático de campos sensibles (emails, tokens, números de tarjeta, claves de API) y verificación en tests (TST-S-011).

## Código de Ejemplo
```php
// config/logging.php
'channels' => [
    'stderr' => [
        'driver' => 'monolog',
        'handler' => StreamHandler::class,
        'with' => ['stream' => 'php://stderr'],
        'formatter' => Monolog\Formatter\JsonFormatter::class,
    ],
],

// Logging con contexto (nunca PII)
Log::info('payment.confirm', [
    'payment_id' => $payment->id,
    'provider'   => $provider,
    'duration_ms'=> $duration,
    'correlation_id' => $correlationId,   // permitido: id técnico
]);

// Enmascarador global de secrets en context
Log::withContext(['request' => $request->all()]); // -> se filtra con Masker
```

```php
// MaskerService: quita keys sensibles recursivamente
const SENSITIVE_KEYS = ['email', 'password', 'token', 'secret', 'api_key',
                        'card_number', 'cvv', 'telegram_token', 'client_secret'];
```

## Criterios de Aceptación
- [ ] Logs JSON estructurados en producción (stderr/file)
- [ ] Formato consistente: timestamp, level, message, context, correlation_id
- [ ] Masker aplicado a contextos (quita/enmascara campos sensibles)
- [ ] Política de retención y rotación de logs
- [ ] Test automático: ningún log de test contiene secretos/PII (TST-S-011)
- [ ] Logs de auditoría (SEC-036) separados de logs operativos

## Notas Técnicas
- Nunca loguear payloads completos de webhooks (pueden contener PII)
- Los IDs técnicos (payment_id, user_id) están permitidos; emails/tokens no
- Los secrets de Telegram/pasarelas jamás se imprimen, ni enmascarados se loguean
- Verificación en CI: escanear salida de tests en busca de patrones sensibles

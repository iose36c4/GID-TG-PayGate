# [[SEC-042]] Backups, DR, PITR y Restore Tests

## Descripción
Plan de **backups y recuperación ante desastres** para un sistema con dinero: backups automáticos de DB (MySQL) y archivos cifrados, **Point-in-Time Recovery (PITR)** con binlogs, retención, almacenamiento offsite, y **restore tests periódicos** (no basta con tener backups: hay que probarlos). Documentado en runbook de DR.

## Código de Ejemplo
```bash
# Backups (comando propio + cron diario)
php artisan backup:run --only=db --encrypt  # 3x/día
php artisan backup:run --only=files --encrypt  # diario

# PITR con binlogs habilitados en MySQL
# my.cnf: log-bin=mysql-bin, expire_logs_days=7
mysqlbinlog --start-datetime="2026-08-04 23:59:00" mysql-bin.000123 | mysql tg_paygate

# Restore test programado (staging aislado)
php artisan backup:restore --from=latest --env=staging --dry-run-check
```

## Criterios de Aceptación
- [ ] Backups automáticos: DB diario (3x) + archivos cifrados (AES)
- [ ] PITR operativo con binlogs (ventana ≥ 24h)
- [ ] Retención definida (ej. 30 días) y almacenamiento offsite cifrado
- [ ] **Restore test mensual automatizado** en staging: validación de integridad
- [ ] Runbook de DR: RTO/RPO definidos, pasos de restauración, comunicación
- [ ] Credenciales de restauración separadas de las de operación
- [ ] Test verificado: restore + auditoría de consistencia (SEC-010)

## Notas Técnicas
- RPO objetivo ≤ 1h (PITR); RTO ≤ 4h (documentado y testeado)
- Los backups cifrados no deben contener secretos en claro (redundancia con SEC-040)
- Restore test: verificar que el ledger reconstruido cuadre (SEC-010) y la reconciliación pase (SEC-019)
- En InfinityFree (alojamiento limitado) documentar la estrategia manual (DOC-010)

# [[SEC-043]] Tests de Concurrencia y Race Conditions

## Descripción
Suite de **tests de concurrencia** sobre operaciones de dinero: doble cobro simultáneo (webhook duplicado concurrente), retiros paralelos del mismo balance, refunds duplicados, expiración vs confirmación de pago en carrera. Verificar que las protecciones de SEC-016/020/021 funcionan bajo carga concurrente real.

## Código de Ejemplo
```php
// tests/Feature/Security/ConcurrencyTest.php
test('doble cobro concurrente -> solo un payment efectivo', function () {
    $payment = Payment::factory()->waitingConfirmation()->create();

    Http::fake([...]); // dos confirmaciones de pasarela

    [$a, $b] = Parallel::run([
        fn () => (new ConfirmPayment)->handle($payment->id, $eventA),
        fn () => (new ConfirmPayment)->handle($payment->id, $eventB),
    ]);

    // Invariantes: 1 solo estado paid, 1 solo entry_group en ledger, invoice paga 1 vez
    expect(Payment::find($payment->id)->state)->toBe('paid');
    expect(LedgerEntry::where('reference_id', $payment->id)->count())->toBe(2); // débito+crédito
    expect($payment->invoice->state)->toBe('paid');
});

test('retiros paralelos no exceden balance', function () {
    $balance = Money::fromDecimal(100, Currency::ARS);
    // 5 retiros de 30 lanzados en paralelo -> solo 3 aprobados
});
```

## Criterios de Aceptación
- [ ] Tests con ejecución paralela real (procesos/threads, no solo `await`)
- [ ] Casos: doble webhook, doble refund, retiros paralelos, expire vs confirm
- [ ] Invariantes verificadas post-carrera: estado, ledger, invoice
- [ ] Cada fallo de carrera identificado se corrige con lock/versión/único
- [ ] Corridos en CI con `--parallel` (Pest) y en job de nightly con más carga
- [ ] Reporte de casos documentados y su control mitigante

## Notas Técnicas
- Usar `spatie/parallel` o subprocesos para concurrency real (Pest `--parallel` ejecuta tests en paralelo)
- Los race conditions de dinero son el riesgo #1 en gateways (RSK-001)
- Si falla la carrera: revisar orden de locks (SEC-021) y `lockForUpdate` (SEC-020)
- Complementar con fault injection (SEC-044)

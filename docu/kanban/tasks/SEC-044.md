# [[SEC-044]] Fault Injection + Chaos Testing en Pagos

## Descripción
Introducir **fallos controlados** para probar resiliencia: proveedor de pago responde 5xx/timeouts, DB/Redis caídos, cola fallando, webhook corrupto, respuestas fuera de orden. Verificar que el sistema no pierde dinero, no dobla cobros y se recupera solo o con alertas claras. Chaos básico en staging.

## Código de Ejemplo
```php
// tests/Feature/Security/FaultInjectionTest.php
test('proveedor 5xx en confirmación -> reintenta y eventualmente cuadra', function () {
    Http::fake([
        'stripe.com/*' => Http::sequence()
            ->pushStatus(500)
            ->pushStatus(503)
            ->push(['status' => 'succeeded']),
    ]);

    $result = (new ConfirmPaymentJob)->handle($delivery);

    expect($result->payment->state)->toBe('paid');
    expect(LedgerEntry::where('reference_id', $result->payment->id)->count())->toBe(2); // sin duplicados
});

test('DB caída durante cobro -> error controlado y sin pagos fantasma', function () {
    DB::shouldReceive('transaction')->andThrow(new ConnectionException('gone'));

    expect(fn () => $checkoutService->create($data))
        ->toThrow(CheckoutUnavailable::class); // 503 limpio, no 500 con stack trace
});

test('webhook fuera de orden (refund antes que payment) -> cola correcta o rechazo claro', ...);
```

## Criterios de Aceptación
- [ ] Fixtures de fallo: proveedor 5xx/timeout, DB/Redis caídos, cola lenta
- [ ] Webhooks fuera de orden manejados (rechazo idempotente o reencolado)
- [ ] Sin duplicación de asientos ni estados incoherentes tras fallos
- [ ] Respuestas de error limpias (503/409), no stack traces
- [ ] Chaos mínimos en staging: matar worker, revocar secreto a mitad de flujo
- [ ] Documentado en runbook (qué pasa cuando X falla)

## Notas Técnicas
- Comenzar con fault injection por tests (determinista) antes que chaos runtime
- El chaos en staging con dinero real NO: usar proveedor sandbox (PUB-016)
- Conectar cada escenario con SEC-029 (retry) y SEC-035 (DLQ)
- Métricas de resiliencia: recovery time, retries usados, DLQ vacía

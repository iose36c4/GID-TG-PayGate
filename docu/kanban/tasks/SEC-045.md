# [[SEC-045]] Replay Testing + Fuzzing de Inputs

## Descripción
Probar **replays** (mismo evento entregado N veces en distinto orden/timing) y **fuzzing** de inputs contra endpoints de dinero y webhooks: payloads mutados, JSON anidado profundo, tipos incorrectos, headers maliciosos. Verificar que idempotencia, validación y verificación de firma rechazan todo lo anómalo sin efectos laterales.

## Código de Ejemplo
```php
// tests/Feature/Security/ReplayTest.php
test('replay de webhook no genera doble asiento', function () {
    $payload = webhookFixture('payment.succeeded');
    $signature = sign($payload);

    $this->postJson('/webhooks/stripe', $payload, ['Stripe-Signature' => $signature]);
    $this->postJson('/webhooks/stripe', $payload, ['Stripe-Signature' => $signature]); // replay
    $this->postJson('/webhooks/stripe', $payload, ['Stripe-Signature' => $signature]); // replay

    expect(LedgerEntry::where('entry_group', $group)->count())->toBe(2); // 1 asiento, no 3
    expect(Payment::where('id', $paymentId)->value('state'))->toBe('paid');
});

// Fuzzing: mutación de payloads con N2T / custom generator
test('fuzz webhook', function (string $mutated) {
    $this->postJson('/webhooks/stripe', json_decode($mutated, true), ['Stripe-Signature' => 'x']);
    // Respuesta siempre 4xx/5xx controlado, NUNCA 500 con excepción cruda
})->with(fuzzCases());
```

## Criterios de Aceptación
- [ ] Replays: mismo webhook 3x (secuencial y concurrente) → sin dobles efectos
- [ ] Replays de eventos con timestamp vencido rechazados (SEC-028)
- [ ] Fuzzing de webhooks, checkout, login y API: payloads malformados/devastadores
- [ ] Ningún fuzz case produce: 500, stack trace, escritura no idempotente, excepción no capturada
- [ ] Presupuesto de fuzzing (minutos por run) y reporte de casos
- [ ] Rincón JSON profundo y campos con tipos incorrectos cubiertos

## Notas Técnicas
- Verificación de firma ANTES de parsear/validar (evita fuzz llegar al negocio)
- Fuzzing con herramientas existentes (N2T, jqfuzz) o generadores propios en Pest
- No confundir replay con idempotencia: replay prueba la misma operación N veces
- Fuzz también headers (Stripe-Signature malformed, Idempotency-Key no UUID)

# [[SEC-050]] Cadencia de Revisión de Seguridad (Security Review)

## Descripción
Definir y ejecutar la **cadencia de revisión de seguridad** como proceso vivo: escaneos automáticos (SAST/DAST/dependencies) en cada CI, revisión manual mensual de logins/webhooks/ledger, revisión trimestral completa (threat model + risk register) y **gate de seguridad pre-release** que bloquea el pase a producción si hay riesgos críticos abiertos. Cierra el ciclo del modelo de amenazas: las revisiones alimentan el Threat Model (SEC-001) y el Risk Register (SEC-003).

## Código de Ejemplo
```markdown
<!-- docu/arquitectura/seguridad/security-review.md -->
# Cadencia de Revisión

## Automático (CI - cada push/PR)
- [ ] PHPStan + Psalm (TST-S-001)
- [ ] composer audit + Dependabot (TST-S-002)
- [ ] Secrets scan (TST-S-003) + tests de autorización (SEC-027)
- [ ] Mutation testing (TST-F-013) + concurrency tests (SEC-043)

## Mensual (release)
- [ ] DAST ZAP en staging (TST-S-004)
- [ ] Revisión de: rate limit abuses, DLQ, reconciliación, audit logs anómalos
- [ ] Verificación de rotación de secretos (SEC-040/030)
- [ ] Restore test de backups (SEC-042)

## Trimestral (revisión completa)
- [ ] Re-validar Threat Model STRIDE (SEC-001) + DFD (SEC-002)
- [ ] Actualizar Risk Register (SEC-003): cerrar/reclasificar riesgos
- [ ] Revisar matriz de acceso (SEC-027) y sesiones (SEC-041)
- [ ] Ejecutar pentest ofensivo guiado (SEC-047/048/049)

## Gate de pre-release (bloqueante)
- [ ] Sin riesgos score ≥ 7 abiertos en Risk Register
- [ ] Cero errores de autorización/concurrencia en CI
- [ ] Reporte firmado por @dev en docu/arquitectura/seguridad/
```

## Criterios de Aceptación
- [ ] `security-review.md` con cadencia automática, mensual y trimestral
- [ ] Checklist pre-release bloqueante integrado al flujo de deploy (Gate)
- [ ] Revisiones mensuales/trimestrales registradas con fecha y hallazgos
- [ ] Cada hallazgo → ticket en el tablero (bug o tarea) con prioridad
- [ ] El Risk Register se actualiza en cada ciclo (nunca queda obsoleto)
- [ ] Primera revisión completa ejecutada antes del hito alfa

## Notas Técnicas
- La seguridad no es un sprint: es un proceso. Esta tarea define el "cómo se mantiene"
- Un hallazgo crítico bloquea el release incluso con features terminadas
- Auditar quién firmó cada revisión (accountability) en el audit log (SEC-036)
- Enlazar con ADM-007 (log de seguridad) y DOC-015 (runbook de incidentes)
